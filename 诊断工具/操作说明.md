# 低压业扩报装首次诊断

只测试“上门服务”节点，保持现有查询条件，只读查询第一页20条一次。不修改生产资源包、不改角标、不覆盖原业务回调、不创建或处理工单。不要把脚本上传为场景包。

## 内网操作

1. 将本目录的 `低压业扩报装诊断.js` 带到内网电脑，用记事本打开。
2. 登录一平台，并通过平时的入口打开、登录营销2.0。需要已有营销隐藏页面；可先打开低压场景让原代码初始化。脚本不会关闭或重新打开业务页面。
3. 打开“低压业扩报装”场景，等待20秒，让原来的重复查询结束。
4. 在这个场景页按 F12，选择 Console（控制台）。不是首页，也不是营销系统页。
5. 将 JS 文件的全部内容复制到控制台执行一次。若客户端禁止粘贴/执行脚本，请交给现场维护人员，不需要修改客户端安全设置。
6. 页面右上角出现诊断面板。等待最多45秒，点击“下载诊断结果”，把生成的 JSON 文件发回。
7. 如果面板没出现，提供控制台错误截图（遮挡业务信息和凭据）。如果面板报超时，也下载结果，不要反复点击执行。
8. 结束后刷新场景页面，即可清除临时回调和面板。无需保存任何页面修改。

## 结果说明

- 本地服务接受指令：只确认本机桥接入口接收，不代表业务系统执行成功。
- script-started：营销页里的脚本执行并成功回传过消息。
- login-token-present：存在登录令牌，不证明令牌有效或权限足够。
- completed：拿到了业务响应结构，仍需看HTTP状态、业务状态及数量字段，不直接认定业务成功。
- token缺失：先登录营销系统，之后再测试。
- 只有桥接返回、没有 script-started：需要定位隐藏营销页面和回传通道；不是“没有待办”的证据。
- data数组长度0：仍需结合业务成功状态，不能单独认定无权限或无待办。

脚本输出只包含响应字段结构、数组长度、数值统计字段、有限业务状态码，不导出数组内的记录，也不导出令牌和原始错误正文。下载前可再次检查。

本次不判断完整总数、不遍历分页、不测试其他八个节点。拿到结果后再决定总数解析和下一步。若账号无法访问营销业务，则须由有正常业务权限的现场人员执行，工具不能替代权限。
